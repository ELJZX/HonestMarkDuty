# HonestMarkDuty

**Версия: 0.2.1**

Информационная система для сменных специалистов по работе с системой маркировки
**«Честный знак»** на пищевом производстве. Девиз проекта — **«Честное выполнение
обязанностей»**. Проект на **Python 3.13 + Django 5.2 + PostgreSQL 17**, инфраструктура
поднимается через **Docker Compose**, администрирование БД — через **pgAdmin 4**.

## Возможности

### Сменная работа

1. **Смены** — график и факт дежурств со статусами «Планируется / Открыта / Закрыта»
   и признаком «принята». Приём и сдача смены доступны как отдельной страницей, так и
   AJAX-кнопками прямо со списка (со всплывающими уведомлениями). Есть проверка склада
   на смене и история состояния оборудования. На странице «Смены» выполняется **лёгкая
   синхронизация** с внешней системой производства (см. ниже) — только чтение.

2. **Сменный журнал** — утверждённая форма: Дата, Дежурный специалист, Время,
   Оборудование/Линия, Время простоя, Действие/Задача, Решение (комментарий), Печ. головка,
   Пробег (км). Записи сгруппированы по смене с объединением ячеек даты и специалиста
   (`rowspan`), текущая смена закреплена сверху и подсвечена; при открытии/закрытии смены
   автоматически добавляются строки «Смену принял +» и «Смену сдал». Есть живой таймер
   длительности.

3. **Чеклисты** — каталог чеклистов с переходом к нужному:
   - **Чеклист осмотра оборудования «Честный знак»** — матрица «группы/автоматы по цехам ×
     проверки» с оценками 1/2/3 и пробегом печатающей головки; статусы **«В работе»** и
     **«Сформирован»**; кнопка **«Закрыть»** переносит чеклист в архив. Архив — таблица
     «Дата / Выполнил / Скачать чеклист». Файл XLSX с цветовой легендой оценок.
   - **Чек лист технического осмотра и обслуживания принтеров Markem Image 9450** —
     таблица «принтеры (серийные номера) × параметры» (счётчики, вязкость, Piezo,
     месторасположение, номера ошибок, комментарии и т.д.). Тот же цикл «в работе → архив»,
     выгрузка в XLSX.

4. **Архив Excel** — единый архив сменного журнала, автоматически обновляемый при сдаче
   смены. Дополнительно: скачивание журнала **по конкретной смене** (кнопка в журнале) и
   **выгрузка за период** (выбор начальной и конечной даты). Имена файлов —
   `smennyy_zhurnal_<дата>.xlsx` и `smennyy_zhurnal_<начало>_<конец>.xlsx`.
   Рядом — архив XLSX чеклистов оборудования.

5. **Сервисы Молвест.Маркировка** — раздел с полезными внешними сайтами: сервисы
   выводятся **кликабельными ссылками**, кнопка «Добавить сервис» открывает форму с полями
   «Название» и «Ссылка».

### Документы

6. **Шаблоны** — готовые шаблоны **технических заключений** и **служебных записок** по
   цехам (Цех №1, Кисломолочный, Цельномолочный, Цех стерильного молока, Творожный,
   Малыш моцарелла, Малыш сырки). Файлы формируются по образцам `.docx` из
   `documents/samples/`; автоматически подставляются дата, ФИО и должность специалиста
   (см. раздел ниже). Если образца нет — формируется документ-заглушка.

7. **Архив документов** — таблица «Дата / Номер / Тип / Цех / Автор» с **живым поиском**
   по любым критериям (номер, автор, цех, дата) и фильтрами по типу и цеху. Кнопка
   **«Добавить документ в архив»** загружает готовый файл: дата, вид (`tz`/`sl`) и цех
   определяются по имени файла/содержимому, номер присваивается по порядку
   (`ТЗ-0001`, `СЛ-0001`), автор — текущий пользователь. Документ можно открыть, скачать
   и распечатать.

### Учет

8. **Склад** — доска «склады → типы → позиции» с иконками типов; позиции с состоянием
   (**«Новое»** или **«Б/у»**), минимальным остатком, историей движений
   (приход / расход / списание / инвентаризация). Отдельный реестр позиций с фильтрами.

9. **Оборудование** — доска «цеха → линии → оборудование» с карточками цехов (метрики
   линий/оборудования/готовности) и изменением порядка перетаскиванием. У оборудования —
   состояние, критичность, IP-адрес, печатающая головка, ответственный, история изменения
   состояния и записи о работах (ТО, ремонт, осмотр, поверка).

10. **Камеры** — стена камер по цехам (маркировочные камеры с ID Camera Control).

### Аналитика и контроль

11. **Дашборд и Статистика** — графики и разделы статистики по специалистам, оборудованию,
    цехам, журналу и чеклистам.

12. **Аудит изменений** — системный `AuditLog` фиксирует каждое создание/изменение/удаление
    с указанием пользователя, объекта и списка изменённых полей.

### Администрирование

13. **Пользователи, Цеха, Площадки** — доступно администратору.

## Быстрый старт (Docker)

### 1. Установите Docker Desktop

Скачайте и установите [Docker Desktop](https://www.docker.com/products/docker-desktop/)
для Windows/macOS/Linux и убедитесь, что он запущен:

```powershell
docker --version
docker compose version
```

### 2. Подготовьте окружение

Скопируйте шаблон `.env.example` в `.env` и при необходимости отредактируйте пароли,
часовой пояс, название организации и параметры синхронизации.

> Название базы данных задаётся переменной `POSTGRES_DB=HonestMarkDuty`.

### 3. Запустите проект

```powershell
docker compose up -d --build
```

Сервис `web` дождётся PostgreSQL, применит миграции, соберёт статику и при
`LOAD_DEMO_DATA=1` загрузит демонстрационные данные.

Проверить логи:

```powershell
docker compose logs -f web
```

### 4. Откройте систему

| Сервис            | Адрес                       |
|-------------------|-----------------------------|
| Приложение        | http://localhost:8000       |
| pgAdmin 4         | http://localhost:5050       |
| Django admin      | http://localhost:8000/admin |

Остановить: `docker compose down` (данные сохраняются в volume).
Полностью удалить данные: `docker compose down -v`.

## Подключение pgAdmin к базе

1. Откройте http://localhost:5050 и войдите (`PGADMIN_DEFAULT_EMAIL` / `PGADMIN_DEFAULT_PASSWORD`).
2. **Add New Server**:
   - **Name**: `HonestMarkDuty`
   - Вкладка **Connection**:
     - Host name/address: `db` (внутри сети Docker Compose)
     - Port: `5432`
     - Maintenance database: `HonestMarkDuty`
     - Username: `honestmark`
     - Password: `honestmark`
3. Сохраните — слева появится база `HonestMarkDuty` со всеми таблицами.

> Если pgAdmin запускается вне Compose, используйте `localhost:5432`.

## Синхронизация смен с внешней системой

Источник данных — существующий сайт производства (Django). Система работает с ним
**только на чтение** (их сайт не изменяется):

- выгрузка событий смены `/main/shift/export_events/` (XLSX: дата/время, ФИО, тип события,
  комментарий);
- таблица графика `/main/shift/` (День, ФИО, начало, конец).

Специалист принимает/сдаёт смену на внешнем сайте, мы лишь отражаем факт у себя.

- **Лёгкий синк** (`quick_sync`) выполняется при открытии страницы «Смены»: один запрос к
  главной внешней системы, с троттлингом (`SHIFT_SYNC_QUICK_TTL`, по умолчанию 120 секунд).
  Если дежурного нет, а смена была принята и открыта — она закрывается.
- **Полный синк** — командой `python manage.py sync_shifts` (обычно по расписанию:
  08:30, 16:45, 20:00). Читает график и события за окно `SHIFT_SYNC_DAYS_BACK` /
  `SHIFT_SYNC_DAYS_AHEAD` дней, создаёт/обновляет смены и записи журнала, выставляет статусы.

Синхронизация выключена по умолчанию (`SHIFT_SYNC_ENABLED=0`) и не мешает странице при
ошибках сети/авторизации.

## Шаблоны документов и автозаполнение

Образцы документов лежат в `documents/samples/` c именами `<код>_<тип>.docx`
(например, `ceh1_tz.docx`). Если образца нет — формируется документ-заглушка.

Поддерживаются:

- плейсхолдеры `{{ ... }}`: `organization`, `city`, `workshop_name`, `workshop_code`,
  `chief`, `chief_position`, `site`, `date`, `date_long`, `number`, `author`,
  `author_position`, `title`;
- **дата в тексте**: токены `«ДАТА» «МЕСЯЦ» «ГОД»` → например `«16» сентября 2026`;
- **сменный специалист**: `От: ...`, `«ФИО»`, `ФАМИЛИЯ/ИНИЦИАЛЫ`, должность в строке
  `Должность:` после `От:` и подпись вида `<должность>  _______ <ФИО>`.

Скачанный файл отдаётся в формате `.docx`; возможна печать версии документа.

## Management-команды

| Команда                         | Назначение                                                        |
|---------------------------------|-------------------------------------------------------------------|
| `python manage.py seed_demo`    | Демонстрационные данные (идемпотентно)                            |
| `python manage.py seed_structure` | Цеха и линии в утверждённом порядке                              |
| `python manage.py seed_cameras` | Маркировочные камеры (по линиям)                                  |
| `python manage.py seed_sklad`   | Склад: позиции, типы, склады (идемпотентно)                       |
| `python manage.py sync_shifts`  | Полная синхронизация смен/журнала с внешней системой              |

`seed_structure`, `seed_sklad`, `seed_cameras` и данные из миграций переносимы в `main`
(данные хранятся в репозитории, а не только в локальной БД). Команда `sync_shifts`
принимает `--days-back`, `--days-ahead`, `--force`.

Версия хранится в файле `VERSION` в корне проекта и читается модулем

```powershell
# 2. Закоммитить и проставить тег
git tag -a v0.2.1 -m "HonestMarkDuty 0.2.1"

```

## Локальный запуск без Docker

> Требуется **Python 3.13** и запущенный PostgreSQL (можно поднять только БД:
> `docker compose up -d db`).

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# В .env укажите POSTGRES_HOST=localhost

python manage.py migrate
python manage.py seed_demo        # демо-данные (необязательно)
python manage.py runserver
```

Для быстрой проверки без PostgreSQL можно использовать SQLite:

```powershell
$env:DB_ENGINE="sqlite"
python manage.py migrate
python manage.py runserver
```

## Роли и права

| Роль                  | Просмотр | Создание/изменение | Удаление, пользователи, цеха |
|-----------------------|:--------:|:------------------:|:----------------------------:|
| Администратор         |    ✓     |         ✓          |              ✓               |
| Сменный специалист    |    ✓     |         ✓          |              —               |
| Наблюдатель           |    ✓     |         —          |              —               |

Права проверяются миксинами `core.mixins` (`AdminRequiredMixin`, `EditorRequiredMixin`).
Редактирование и удаление документов и чеклистов доступно только администратору.
Любое изменение фиксируется в аудите с указанием автора и набора изменённых полей.

## Переменные окружения

Все параметры — в `.env` (шаблон `.env.example`). Ключевые:

| Переменная                 | Назначение                                                    |
|----------------------------|---------------------------------------------------------------|
| `DJANGO_SECRET_KEY`        | Секретный ключ Django                                         |
| `DJANGO_DEBUG`             | `1` — режим разработки                                        |
| `DJANGO_ALLOWED_HOSTS`     | Разрешённые хосты                                             |
| `POSTGRES_DB`              | Имя базы (`HonestMarkDuty`)                                   |
| `POSTGRES_HOST`            | `db` в Docker, `localhost` локально                           |
| `ORGANIZATION_NAME`        | Название организации в документах                             |
| `ORGANIZATION_CITY`        | Город для шаблонов документов                                 |
| `LOAD_DEMO_DATA`           | Загружать демо-данные при старте                              |
| `CREATE_SUPERUSER`         | Создать суперпользователя при старте                          |
| `DB_ENGINE`                | `postgres` (по умолчанию) или `sqlite`                        |
| `SHIFT_SYNC_ENABLED`       | Включить синхронизацию смен с внешней системой                |
| `SHIFT_SYNC_URL`           | Адрес внешней системы                                         |
| `SHIFT_SYNC_USER` / `SHIFT_SYNC_PASSWORD` | Доступы к внешней системе                     |
| `SHIFT_SYNC_DAYS_BACK` / `SHIFT_SYNC_DAYS_AHEAD` | Окно синхронизации (дней)           |
| `SHIFT_SYNC_CREATE_USERS`  | Создавать пользователей по ФИО из графика                     |
| `SHIFT_SYNC_QUICK_TTL`     | Троттлинг лёгкого синка, секунд                               |
