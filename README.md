# HonestMarkDuty

**Версия: 0.0.3**

Информационная система для сменных специалистов по работе с системой маркировки
**«Честный знак»** на пищевом производстве. Девиз проекта — **«Честное выполнение
обязанностей»**. Проект на **Python 3.13 + Django 5.2 + PostgreSQL 17**, инфраструктура
поднимается через **Docker Compose**, администрирование БД — через **pgAdmin 4**.
Интерфейс выполнен в тёмном минималистичном стиле [opencode.ai](https://opencode.ai).

## Возможности

Реализованы все 7 функций первого этапа:

1. **Склад инструментов и запчастей** — позиции на полках с состоянием и степенью износа,
   минимальными остатками, историей движений (приход/расход/списание/инвентаризация).
2. **Приём и сдача смены** — открытие смены в начале дня, закрытие в конце, проверка склада,
   фиксация состояния оборудования и замечаний.
3. **Сменный журнал** — обращения с временем, местом заявки, описанием проблемы и решения,
   статусами и приоритетами. **При сдаче смены журнал автоматически выгружается в Excel**
   и попадает в архив.
4. **Прозрачность изменений** — системный `AuditLog` фиксирует каждое создание/изменение/удаление
   с указанием пользователя, объекта и списка изменённых полей. Раздел «Аудит изменений».
5. **Документы** — шаблоны технических заключений, служебных записок и т.д. с
   плейсхолдерами вида `{{ workshop_name }}`, `{{ chief }}`, `{{ date_long }}`.
   Поля **автоматически заполняются для каждого цеха**; документ можно открыть,
   скачать в **DOCX**, распечатать.
6. **Оборудование площадок** — реестр оборудования с состоянием, критичностью,
   историей изменений состояния и записями о работах (ТО, ремонт, поверка).
7. **Статистика** — дашборд с графиками и раздел статистики по специалистам,
   оборудованию, цехам и журналу.

## Быстрый старт (Docker)

### 1. Установите Docker Desktop

Скачайте и установите [Docker Desktop](https://www.docker.com/products/docker-desktop/)
для Windows/macOS/Linux и убедитесь, что он запущен:

```powershell
docker --version
docker compose version
```

### 2. Подготовьте окружение

Файл `.env` уже создан с dev-настройками. При необходимости отредактируйте
пароли, часовой пояс и название организации.

> Название базы данных задаётся переменной `POSTGRES_DB=HonestMarkDuty`.

### 3. Запустите проект

```powershell
docker compose up -d --build
```

Сервис `web` дождётся PostgreSQL, применит миграции, соберёт статику и при
`LOAD_DEMO_DATA=1` загрузит демонстрационные данные.

Проверить логи:

```powershell
docker compose logs -f web
```

### 4. Откройте систему

| Сервис            | Адрес                       |
|-------------------|-----------------------------|
| Приложение        | http://localhost:8000       |
| pgAdmin 4         | http://localhost:5050       |
| Django admin      | http://localhost:8000/admin |

Остановить: `docker compose down` (данные сохраняются в volume).
Полностью удалить данные: `docker compose down -v`.

## Версионирование

Версия хранится в файле `VERSION` в корне проекта и читается модулем
`config/version.py`. Текущая версия — **0.0.3**. Она выводится в правом верхнем углу под
кнопкой «Выход» и на странице входа.

Выпуск новой версии:

```powershell
# 1. Обновить файл VERSION и config/version.py
# 2. Закоммитить и проставить тег
git tag -a v0.0.3 -m "HonestMarkDuty 0.0.3"
git push origin main --tags
```

## Подключение pgAdmin к базе

1. Откройте http://localhost:5050 и войдите (`PGADMIN_DEFAULT_EMAIL` / `PGADMIN_DEFAULT_PASSWORD`).
2. **Add New Server**:
   - **Name**: `HonestMarkDuty`
   - Вкладка **Connection**:
     - Host name/address: `db` (внутри сети Docker Compose)
     - Port: `5432`
     - Maintenance database: `HonestMarkDuty`
     - Username: `honestmark`
     - Password: `honestmark`
3. Сохраните — слева появится база `HonestMarkDuty` со всеми таблицами.

> Если pgAdmin запускается вне Compose, используйте `localhost:5432`.

## Локальный запуск без Docker

> Требуется **Python 3.13** и запущенный PostgreSQL (можно поднять только БД:
> `docker compose up -d db`).

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# В .env укажите POSTGRES_HOST=localhost

python manage.py migrate
python manage.py seed_demo        # демо-данные (необязательно)
python manage.py runserver
```

Для быстрой проверки без PostgreSQL можно использовать SQLite:

```powershell
$env:DB_ENGINE="sqlite"
python manage.py migrate
python manage.py runserver
```

## Роли и права

| Роль                  | Просмотр | Создание/изменение | Удаление, пользователи, цеха |
|-----------------------|:--------:|:------------------:|:----------------------------:|
| Администратор         |    ✓     |         ✓          |              ✓               |
| Сменный специалист    |    ✓     |         ✓          |              —               |
| Наблюдатель           |    ✓     |         —          |              —               |

Права проверяются миксинами `core.mixins`. Любое изменение фиксируется в аудите
с указанием автора и IP-независимого набора изменённых полей.

## Переменные окружения

Все параметры — в `.env` (шаблон `.env.example`). Ключевые:

| Переменная                 | Назначение                                |
|----------------------------|-------------------------------------------|
| `DJANGO_SECRET_KEY`        | Секретный ключ Django                     |
| `DJANGO_DEBUG`             | `1` — режим разработки                    |
| `POSTGRES_DB`              | Имя базы (`HonestMarkDuty`)               |
| `POSTGRES_HOST`            | `db` в Docker, `localhost` локально       |
| `ORGANIZATION_NAME`        | Название организации в документах         |
| `ORGANIZATION_CITY`        | Город для шаблонов документов             |
| `LOAD_DEMO_DATA`           | Загружать демо-данные при старте          |
| `CREATE_SUPERUSER`         | Создать суперпользователя при старте      |

## Автозаполнение документов

В шаблонах доступны плейсхолдеры:

```
{{ organization }} {{ city }}
{{ workshop_name }} {{ workshop_code }} {{ chief }} {{ chief_position }} {{ site }}
{{ date }} {{ date_long }} {{ number }}
{{ author }} {{ author_position }}
```

Все поля, кроме перечисленных, запрашиваются у пользователя в форме и подставляются
в документ. Итог можно скачать в `.docx` или распечатать.
