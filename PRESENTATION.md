# HonestMarkDuty

### Информационная система сменных специалистов по цифровой маркировке «Честный знак»

**Версия 1.0.1** · Python 3.13 · Django 5.2 · PostgreSQL 17 · Docker

_Девиз: «Честное выполнение обязанностей»_

---

## Проблема

- Сменный журнал и чеклисты велись в разрозненных Excel-файлах.
- Данные не синхронизировались между специалистами и сменами.
- Ручное формирование отчётности по утверждённым формам занимало время.
- Требовался контроль складских остатков и состояния оборудования в одной системе.

---

## Решение

Единое веб-приложение для сменной работы:

- **Смены** — график и факт дежурств, приём/сдача, синхронизация с внешней системой (только чтение).
- **Сменный журнал** — утверждённая форма, группировка по сменам, подсветка текущей смены.
- **Чеклисты** — осмотр «Честный знак» и обслуживание принтеров Markem Image 9450.
- **Склад и оборудование** — позиции, движения, состояние, ТО и ремонты.
- **Документы** — шаблоны технических заключений и служебных записок по цехам.
- **Аналитика и аудит** — дашборд KPI и журнал всех изменений.

```

├─ config/        # настройки, версия, корневые URL
├─ accounts/      # пользователи и роли
├─ core/          # цеха, линии, площадки, аудит, миксины

├─ equipment/     # цеха → линии → оборудование, камеры, ТО
├─ documents/     # шаблоны DOCX и архив документов
├─ inventory/     # склад: склады, типы, позиции, движения
├─ services/      # сервисы «Молвест.Маркировка»
├─ analytics/     # дашборд
└─ templates/     # HTML-шаблоны, static/css/app.css
```

## Роли и права

| Роль | Просмотр | Создание/изменение | Удаление, справочники |
|------|:--------:|:------------------:|:---------------------:|
| Администратор | ✓ | ✓ | ✓ |
| Сменный специалист | ✓ | ✓ | — |
| Наблюдатель | ✓ | — | — |

Права — миксинами `AdminRequiredMixin` / `EditorRequiredMixin`.
Любое изменение фиксируется в `AuditLog` с автором и набором полей.
Администрирование справочников — в Django admin (`/admin/`).

---

## Ключевые сценарии

1. **Приём смены** → журнал пополняется записью «Смену принял +».
2. **Работа специалиста** → записи журнала, проверки склада, чеклисты.
3. **Сдача смены** → запись «Смену сдал», обновление единого Excel-архива.
4. **Выгрузка** → архив за период или по конкретной смене.
5. **Отчётность** → XLSX по утверждённым формам, шаблоны DOCX по цехам.

## Синхронизация смен

- Источник — внешний сайт производства; система работает **только на чтение**.
- **Лёгкий синк** — при заходе на страницу «Смены» (троттлинг `SHIFT_SYNC_QUICK_TTL`).
- **Полный синк** — команда `python manage.py sync_shifts` (по расписанию).
- При ошибках сети/авторизации страница продолжает работать.

## Развёртывание

```powershell
cp .env.example .env      # настроить пароли и параметры
docker compose up -d --build
```

- `web` ждёт PostgreSQL, применяет миграции, собирает статику.
- Приложение: http://localhost:8000 · pgAdmin: http://localhost:5050 · admin: `/admin/`.

## Качество

- Полный прогон тестов: `docker compose exec web python manage.py test`.
- Покрытие ключевых модулей — около **99%**.
- Данные справочников переносимы в `main` через миграции и идемпотентные
